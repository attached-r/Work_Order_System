# 工单状态机与流转规则

## 状态一览

工单共有 8 个状态，状态值从 0 到 7：

- 0 待审核：提单人已提交，等待本部门审核人审核。
- 1 待派单：审核已通过，等待派单人分配处理人。
- 2 处理中：已经派单给处理人，处理人正在处理；验收退回、转派后也仍然处于这个状态。
- 3 待验收：处理人已处理完成，等待提单人验收。
- 4 已完成：提单人验收通过，流程结束，是终态。
- 5 已驳回：审核不通过，退回提单人修改；不是终态，修改后可以重新提交。
- 6 已取消：提单人主动撤回或取消，是终态。
- 7 已超时：超过处理期限，系统自动关闭，是终态。

终态只有三种：已完成、已取消、已超时。进入终态后不能再执行审核、派单、处理、验收、撤回等动作。

## 正常流转主链路

一条正常工单的主链路是：

待审核（0）→ 审核通过 → 待派单（1）→ 派单 → 处理中（2）→ 处理完成 → 待验收（3）→ 验收通过 → 已完成（4）。

主链路一共五个环节：提单、审核、派单、处理、验收。任何一个环节没有完成，工单都不会进入已完成状态。

## 审核驳回与重新提交

审核人在「待审核（0）」状态下可以做出两种决定：

- 审核通过：状态从 0 变为 1（待派单）。
- 审核驳回：状态从 0 变为 5（已驳回），驳回原因会记录在工单备注里。

被驳回的工单由提单人本人修改后重新提交。重新提交需要修改工单的权限，提交后状态从 5 回到 0（待审核），并重新进入审核环节。

已驳回不是终态。只要工单还没有被取消或超时关闭，提单人就可以修改并重新提交。

## 派单与转派

审核通过后，工单进入「待派单（1）」。派单人在本部门范围内选择一名处理人，执行派单：

- 派单后状态从 1 变为 2（处理中），处理人字段被写入。
- 派单需要派单权限，并且只能处理本部门的工单。

工单处于「处理中（2）」时可以转派：把处理人从当前人员改为另一名人员，状态仍然是 2（处理中）。转派需要转派权限；默认角色配置中，处理人角色具备该权限。

## 处理完成与验收

处理人处理完成后，把工单从「处理中（2）」推进到「待验收（3）」。只有当前处理人本人可以执行处理完成。

工单进入「待验收（3）」后，由提单人本人验收：

- 验收通过：状态从 3 变为 4（已完成），流程结束。
- 验收退回：状态从 3 回到 2（处理中），处理人需要继续处理。

验收动作需要验收权限，并且只有提单人本人可以验收自己的工单。

## 撤回与取消

提单人本人在以下状态可以撤回或取消工单：待审核（0）、待派单（1）、处理中（2）、已驳回（5）。

撤回或取消后，状态变为 6（已取消），流程结束，是终态。已经进入待验收、已完成、已超时或已取消的工单不能撤回。

撤回或取消需要撤回权限，并且只能由提单人本人操作。

## 超时关闭

每张工单可以设置一个处理期限。超过期限仍未完成的工单，由系统自动关闭，状态变为 7（已超时）。

可能被超时关闭的状态包括：待审核（0）、待派单（1）、处理中（2）、待验收（3）。已驳回、已完成、已取消的工单不会被超时关闭。

超时关闭是系统行为，不需要人工操作；关闭后是终态，不能继续处理。

## 状态与可执行操作对照

- 待审核（0）：审核人可审核通过或驳回；提单人可撤回。
- 待派单（1）：派单人可派单；提单人可撤回。
- 处理中（2）：处理人可处理完成或转派；提单人可撤回。
- 待验收（3）：提单人可验收通过或退回；不能被撤回，只能等待验收或超时。
- 已驳回（5）：提单人可修改后重新提交，或直接取消。
- 已完成（4）、已取消（6）、已超时（7）：终态，没有后续流转动作。

当操作与当前状态不匹配时，系统会拒绝该操作，并提示当前状态不允许。
