# 工单类型与字段说明

## 三种工单类型

工单类型用于区分诉求的性质，共有三种：

- 故障报修：设备、系统、网络等出现故障，需要排查修复。例如服务器宕机、网络中断、软件报错。
- 资源申请：申请服务器、带宽、软件许可等资源。需要填写资源明细，说明资源类别、名称、数量和单位。
- 需求变更：对已有系统或流程提出调整、优化、新增功能等诉求。

## 三档优先级

优先级用于表达紧急程度，共有三档：

- 高：影响核心业务、造成较大范围不可用，需要尽快处理。
- 中：对业务有影响但可以短时等待，是默认优先级。
- 低：不影响主流程的优化类或一般性诉求，可以按计划处理。

优先级是提单时的参考信息，不会自动改变工单状态；实际处理顺序由派单人和处理人安排。

## 工单主要字段

- 工单编号：提交时由系统生成，全局唯一，用于沟通和查找工单。工单编号与数据库内部编号不是一回事，日常沟通应以工单编号为准。
- 提单人：提交工单的用户。
- 归属部门：提交时提单人所在部门的快照，审核与派单按这个部门隔离。
- 处理人：被派单的人员；派单之前为空。
- 标题：一句话概括诉求，便于列表识别。
- 描述：问题的详细说明、复现步骤或申请理由。
- 工单类型：故障报修、资源申请或需求变更。
- 优先级：高、中、低。
- 状态：0 到 7 的流程状态，具体含义见状态机说明。
- 备注：用于记录驳回原因、关闭说明等补充信息。
- 创建时间与更新时间：工单的提交时间和最近一次变更时间。
- 处理期限：工单要求完成的时间；超期后系统会自动关闭。
- 版本号：用于并发控制，避免两个人同时修改造成覆盖，普通用户无需关注。
- 删除标记：被逻辑删除的工单不会出现在列表和详情中。

## 资源明细

资源申请类工单可以附带多条资源明细。每条明细包含：

- 资源类别：例如服务器、带宽、软件许可。
- 资源名称或规格描述：例如「8 核 16G 云服务器」「100Mbps 专线」。
- 数量：申请的数量，支持小数。
- 单位：台、MBps、个等。
- 申请说明：可选的补充说明。

资源明细没有独立状态，随工单主状态一起流转：工单处理完成，资源申请也就完成；工单被驳回或取消，资源申请同样终止。

## 操作日志类型

每次状态流转都会留下一条操作记录，操作类型共有十种：

- 提交：创建并提交工单，或驳回后重新提交。
- 审核通过：审核人同意。
- 审核驳回：审核人拒绝，工单退回提单人。
- 派单：派单人指定处理人。
- 处理完成：处理人标记处理完毕。
- 验收通过：提单人确认结果，工单完成。
- 退回处理：提单人验收不通过，工单回到处理中。
- 转派：把工单从一名处理人转给另一名处理人。
- 撤回或取消：提单人主动终止工单。
- 超时关闭：系统因超过处理期限自动关闭。

操作记录会保存操作人、变更前后的状态、目标处理人和操作时间，用于追溯「谁在什么时候做了什么」。
