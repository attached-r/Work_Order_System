# 角色、权限与数据范围

## 五个角色

系统内置五个角色：

- 提单人（SUBMITTER）：创建、提交、修改、撤回或取消工单，并对处理结果进行验收。
- 审核人（REVIEWER）：审核本部门的提单，决定通过或驳回。
- 派单人（DISPATCHER）：查看本部门待派单工单，并分配处理人。
- 处理人（HANDLER）：处理分配给自己的工单，支持处理完成与转派。
- 管理员（ADMIN）：管理用户、角色、部门，并查看全部工单。

一个用户可以拥有一个或多个角色，最终权限是各角色权限的并集。

## 十个权限码

系统共有十个权限码：

- workorder:create：提交工单。
- workorder:modify：修改工单，包括驳回后修改并重新提交。
- workorder:withdraw：撤回或取消工单。
- workorder:accept：验收工单，包括验收通过和验收退回。
- workorder:query：查询工单列表与详情。
- workorder:review：审核工单。
- workorder:dispatch：派单。
- workorder:process：处理工单并标记处理完成。
- workorder:transfer：转派工单。
- user:manage：用户、角色、部门管理，属于管理类权限。

## 角色与权限对应关系

默认种子数据的角色权限如下：

- 提单人：提交、修改、撤回、验收、查询。
- 审核人：审核、查询。
- 派单人：派单、查询。
- 处理人：处理、转派、查询。
- 管理员：全部十个权限。

注意：权限是按角色授予的，不是按人写死的。用户改了角色，权限会随角色变化；系统对权限有短时缓存，刚改完权限可能需要等待一小段时间才生效。

## 列表的数据范围

工单列表不是所有人都能看到全部数据，系统按角色限定数据范围：

- 提单人：只能看到自己提交的工单。
- 审核人：可以看到本部门的工单。
- 派单人：可以看到本部门的工单。
- 处理人：只能看到分配给自己的工单。
- 管理员：可以看到全部工单。

一个人同时拥有多个角色时，数据范围按角色分别生效，再合并结果。例如同时是提单人和处理人，既能看自己提交的，也能看分配给自己的。

## 详情的数据范围

查看单张工单详情时，同样受数据范围约束：

- 提单人只能查看自己提交的工单。
- 审核人、派单人只能查看本部门的工单。
- 处理人只能查看分配给自己的工单。
- 管理员可以查看全部。

如果一张工单既不属于本人、也不属于本部门，即使知道工单编号，也会被拒绝访问。

## 部门隔离说明

审核与派单都按「工单归属部门」隔离。工单的归属部门在提交时确定，是提交人当时所在部门的快照。

提交之后即使提交人调换了部门，已经提交的工单仍然归属原部门，仍由原部门的审核人和派单人处理。这是为了保证流程责任链稳定。

管理员没有部门限制，可以跨部门查看和处理。
